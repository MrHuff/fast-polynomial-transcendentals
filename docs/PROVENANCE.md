# Provenance

This document records where the standalone implementation and retained evidence
came from, and which claims the available provenance supports. Commit hashes
identify source snapshots; they do not repair missing commands, dirty-worktree
deltas, runtime metadata, or external assets.

## Provenance classes

- **Extracted and modified:** code adapted into this standalone repository and
  changed to remove the original training-framework or infrastructure coupling.
- **Materialized historical evidence:** a retained output that can be inspected
  offline but was not generated by this standalone repository.
- **Historical source-derived:** configuration reconstructed from a preserved
  source snapshot rather than attested by the original runtime output.
- **New measurement:** output produced from a recorded revision of this
  repository with a complete runtime record.
- **Blocked:** an exact rerun lacks code, configuration, raw output, external
  assets, or another essential input.

## Paired pre-training boundary

The retained CSV can regenerate the plotted curves. It contains sampled points
from one historical baseline trajectory and one historical polynomial
trajectory per case. Checkpoints or minibatches along one trajectory are not
independent repetitions.

This repository has no exact pre-training rerun target. It does not distribute
the training data, checkpoints, original distributed launcher, or enough
configuration to establish identical initialization and data order. Any future
large-scale rerun needs a new manifest, explicit licenses for every model and
dataset asset, and newly recorded outputs.

## Model and dataset provenance

Model weights, tokenizers, and evaluation datasets are external inputs and are
not redistributed here. Their names in a configuration identify intended
inputs; they do not grant access or a redistribution license. A reviewer who
runs an open-weight experiment must record the exact immutable model and
tokenizer revisions and comply with each provider's terms. Dataset and task
versions, preprocessing, few-shot examples, and evaluator revision are part of
the scientific provenance.

## Producing new evidence

New results should use the common envelope in `schemas/result-v1.json` and add
experiment-specific fields without deleting required metadata. Store the
complete command as an argument array, not a shell string containing secrets.
Hash material inputs and outputs. Record a dirty tree as dirty; do not replace
that fact with the nearest commit hash. Preserve raw per-round samples whenever
practical.
